# AGENTS.md — Rules for Coding Agents

> This repository follows the pnpm/Biome/TypeScript/Vitest stack generated by [cookiecutter-project-kit](https://github.com/samuelduchesne/cookiecutter-project-kit).

## Environment & Install

- Use **pnpm** for all dependency management and scripts (never npm or yarn).
- Install dependencies: `pnpm install`
- Add a dependency: `pnpm add <package>`
- Add a dev dependency: `pnpm add -D <package>`
- Node.js {{ cookiecutter.node_version }} or newer (see `.nvmrc`).

## Quality Gate (run before proposing changes)

```bash
# Lint and format (writes fixes)
pnpm format

# Type check
pnpm typecheck

# Run tests
pnpm test

# Build
pnpm build
```

Or use the Makefile: `make check && make test`

biome.json               # Lint and format rules

## Code Conventions

### Style
- **Line length**: 120 characters (configured in biome.json)
- **Modules**: ES modules only; use `.js` extensions in relative imports (`import { x } from "./x.js"`)
- **Types**: strict TypeScript; no `any`, type every exported function's parameters and return value
- **Type-only imports**: use `import type` (enforced by `verbatimModuleSyntax`)
- **Docs**: TSDoc comments on every export

### Errors
- Throw specific built-in errors (`TypeError`, `RangeError`) or subclasses of `Error` with clear messages
- Never swallow errors silently

## Testing

- Tests live in `tests/` and are named `<module>.test.ts`
- Import from `../src/<module>.js`
- Run a single file: `pnpm vitest run tests/<module>.test.ts`
- Cover the error paths, not only the happy path

## Common Tasks for AI Agents

### Adding a New Module
1. Create `src/new-module.ts`
2. Re-export its public API from `src/index.ts`
3. Create `tests/new-module.test.ts` with tests
4. Run `make check && make test`

### Adding a Dependency
1. `pnpm add <package>` (or `pnpm add -D <package>` for dev dependencies)
2. Import and use it in code
3. Commit `package.json` and `pnpm-lock.yaml` together

### Fixing a Bug
1. Write a failing test that reproduces the bug
2. Fix the code until the test passes
3. Run the full suite: `make test`
4. Run quality checks: `make check`

### Updating the Changelog
1. Find the `## [Unreleased]` section at the top of `CHANGELOG.md`
2. Add a bullet under the matching category heading, creating the heading if it is missing:
   ```markdown

   ### Fixed

   - Reject an empty name in `greet` instead of returning `Hello, !`.
   ```
3. Skip internal-only changes (refactors, tests, CI) that users won't notice
