## Code Conventions

### Style
- **Line length**: 120 characters (configured in pyproject.toml)
- **Imports**: Use `from __future__ import annotations` in all files
- **Docstrings**: Google or NumPy style; required for all public APIs

### Type Hints
- All functions must have complete type annotations
- Use `-> None` explicitly for functions that don't return a value
- Prefer `list[T]`, `dict[K, V]` over `List[T]`, `Dict[K, V]` (Python 3.9+)
- Use `| None` over `Optional[T]` for nullable types

### Data Structures
- Prefer **dataclasses** or **Pydantic models** over plain dictionaries for structured data
- Document dataclass fields with inline docstrings:
  ```python
  @dataclass
  class Config:
      host: str
      """The hostname to connect to."""
      port: int = 8080
      """The port number (default: 8080)."""
  ```

### Error Handling
- Use specific exception types; avoid bare `except:`
- Document exceptions in docstrings with `Raises:` section
- Fail fast: validate inputs at function boundaries

## Testing Guidelines

### Running Tests
```bash
# Run all tests
uv run pytest

# Run specific test file
uv run pytest tests/test_module.py

# Run specific test function
uv run pytest tests/test_module.py::test_function_name

# Run with verbose output
uv run pytest -v

# Run with coverage
uv run pytest --cov
```

### Writing Tests
- Mirror source structure in `tests/` directory
- Use descriptive test names: `test_<function>_<scenario>_<expected>`
- Use pytest fixtures for shared setup (define in `conftest.py`)
- Test both success cases and error conditions
- Prefer `pytest.raises` for exception testing:
  ```python
  def test_invalid_input_raises_value_error():
      with pytest.raises(ValueError, match="expected pattern"):
          function_under_test(invalid_input)
  ```

### Parameter Schema (Important!)

Pipeline parameters in `params.yaml` are validated with Pydantic. When modifying parameters:

1. Update `{% if cookiecutter.layout == 'src' %}src/{% endif %}{{ cookiecutter.project_slug }}/schemas/params.py` with new/changed parameter definitions
2. Regenerate schema: `uv run python -c "from {{ cookiecutter.project_slug }}.schemas import PipelineParams; PipelineParams.generate_json_schema()"`
3. Commit both `params.yaml` and schema files together

Never modify `params.yaml` without updating the schema.

  - `fix:` bug fix

  - `chore:` maintenance tasks

## Common Tasks for AI Agents

### Adding a New Module
1. Create `{% if cookiecutter.layout == "src" %}src/{% endif %}{{ cookiecutter.project_slug }}/new_module.py`
2. Add exports to `{% if cookiecutter.layout == "src" %}src/{% endif %}{{ cookiecutter.project_slug }}/__init__.py` if public
3. Create `tests/test_new_module.py` with tests
4. Run `make check && make test`

### Adding a Dependency
1. `uv add <package>` (or `uv add --dev <package>` for dev dependencies)
2. Import and use in code
3. Run `make check` to verify no issues

### Fixing a Bug
1. Write a failing test that reproduces the bug
2. Fix the code until the test passes
3. Run full test suite: `make test`
4. Run quality checks: `make check`

### Refactoring
1. Ensure tests exist for code being refactored
2. Make changes incrementally
3. Run tests after each change: `uv run pytest`
4. Run type checker frequently: `uv run {{ cookiecutter.type_checker }}{% if cookiecutter.type_checker in ["ty", "pyrefly"] %} check{% endif %}`
